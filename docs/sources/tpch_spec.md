# TPC-H — excerpts from the standard specification

> Excerpts from the TPC Benchmark(TM) H Standard Specification, Revision 3.0.1,
> published by the Transaction Processing Performance Council at
> https://www.tpc.org/tpc_documents_current_versions/pdf/tpc-h_v3.0.1.pdf
>
> This file exists to test the grounding mechanism against documentation that was
> not written for this project. The tables it describes (`samples.tpch`) ship with
> Databricks and were not created here either. Neither side of the test was authored
> by whoever is running it, which is the whole point: a test where you write both the
> question and the answer cannot fail, and a test that cannot fail proves nothing.

## Coded column values

The single-character columns are the reason this test is worth running. Their values
are `N`, `A`, `R`, `O`, `F`, `P`. Nothing in the data says what they mean.

**L_RETURNFLAG** is set to a value selected as follows: if L_RECEIPTDATE is on or
before CURRENTDATE then either "R" or "A" is selected at random, else "N" is
selected.

**L_LINESTATUS** is set to "O" if L_SHIPDATE is after CURRENTDATE, and "F"
otherwise.

**O_ORDERSTATUS** is set to "F" if all lineitems of this order have L_LINESTATUS set
to "F"; to "O" if all lineitems of this order have L_LINESTATUS set to "O"; and to
"P" otherwise.

**O_SHIPPRIORITY** is set to 0 for every row.

## Table layouts

CUSTOMER carries C_CUSTKEY as primary key, with C_NATIONKEY a foreign key to
N_NATIONKEY, and C_MKTSEGMENT as fixed text of size 10 drawn from the Segments list.

ORDERS carries O_ORDERKEY as primary key and O_CUSTKEY as a foreign key to
C_CUSTKEY. O_TOTALPRICE is computed as the sum of L_EXTENDEDPRICE * (1 + L_TAX) *
(1 - L_DISCOUNT) over all lineitems of the order, so it already includes tax and
discount and must not have them applied again. O_ORDERPRIORITY is a random string
from the Priorities list. O_CLERK is text appended with at least nine digits with
leading zeros, in the form "Clerk#" followed by a value.

Orders are not present for all customers. O_CUSTKEY is generated such that
O_CUSTKEY modulo 3 is not zero, so every third customer in C_CUSTKEY order is not
assigned any order. One third of customers have no order in the database. This is
deliberate, to exercise handling of "dead data" when joining tables.

LINEITEM has the compound primary key L_ORDERKEY, L_LINENUMBER. L_ORDERKEY is a
foreign key to O_ORDERKEY. L_PARTKEY and L_SUPPKEY together form a compound foreign
key to PS_PARTKEY and PS_SUPPKEY. Each order has a random number of lineitems within
1 to 7.

L_EXTENDEDPRICE is L_QUANTITY multiplied by the P_RETAILPRICE of the part identified
by L_PARTKEY. It is therefore a gross line amount before discount and tax;
L_DISCOUNT is a rate between 0.00 and 0.10 and L_TAX a rate between 0.00 and 0.08,
both expressed as fractions rather than percentages.

L_SHIPDATE is O_ORDERDATE plus a random value of 1 to 121 days. L_COMMITDATE is
O_ORDERDATE plus 30 to 90 days. L_RECEIPTDATE is L_SHIPDATE plus 1 to 30 days. The
three dates are distinct events: promised, dispatched and received.

## Reference tables

NATION holds exactly 25 rows, with N_NATIONKEY a unique value between 0 and 24 and
N_REGIONKEY a foreign key to R_REGIONKEY. The series is fixed: (0, ALGERIA, 0),
(1, ARGENTINA, 1), (2, BRAZIL, 1), (3, CANADA, 1), (4, EGYPT, 4), (5, ETHIOPIA, 0),
(6, FRANCE, 3), (7, GERMANY, 3), (8, INDIA, 2), (9, INDONESIA, 2), (10, IRAN, 4),
(11, IRAQ, 4), (12, JAPAN, 2), (13, JORDAN, 4), (14, KENYA, 0), (15, MOROCCO, 0),
(16, MOZAMBIQUE, 0), (17, PERU, 1), (18, CHINA, 2), (19, ROMANIA, 3),
(20, SAUDI ARABIA, 4), (21, VIETNAM, 2), (22, RUSSIA, 3), (23, UNITED KINGDOM, 3),
(24, UNITED STATES, 1).

REGION holds exactly 5 rows: (0, AFRICA), (1, AMERICA), (2, ASIA), (3, EUROPE),
(4, MIDDLE EAST).

## Parts and suppliers

PART carries P_PARTKEY as primary key. P_NAME is generated by concatenating five
unique randomly selected colour and texture words separated by single spaces, so it
is a synthetic label and not a product description. P_MFGR is "Manufacturer#"
followed by a digit from 1 to 5. P_BRAND is "Brand#" followed by two digits derived
from the manufacturer. P_RETAILPRICE is computed from P_PARTKEY by formula, not
drawn at random, so it is not an independent economic quantity.

PARTSUPP holds four rows for each row in PART, one per supplier. PS_AVAILQTY is a
random value from 1 to 9,999 and PS_SUPPLYCOST a random value from 1.00 to 1,000.00.

The comment columns across every table (C_COMMENT, O_COMMENT, L_COMMENT, and the
rest) hold generated filler text of a specified length range. They carry no meaning
and exist to give the rows realistic width.
